**Reason for the exception (presented to the maintainer, never self-granted):** PR-1's
raw diff is dominated by **generated/tool-owned lines nobody reviews line by line**
— template output (~150), shadcn output (~215), and the lockfile delta
(~1,600–2,500). That portion is **atomic**: the template + toolchain + lockfile must
land together or the app does not install/build, and no honest slicing pass can
split it (chained-pr: "generated/vendor diff cannot split cleanly"). The
**hand-written reviewable core stays ~293 ≈ 300 ≤ 400** — docs (~77), shell +
config (~83), `apiClient.ts` + proving test (81), CI job (~28). Recommended framing
for the maintainer: *accept `size:exception` scoped to the generated/tool-owned
lines*; the alternative (docs commit as its own PR) is rejected as extra overhead
with no review benefit, since docs-first is already satisfied in-branch.

**`--max-changed-lines: 3200` — recorded reason:** the raw total (incl. the lockfile
at the top of the estimate range) must fit the attempt ledger **once, up front**.
The Phase 3 PR-2 failure — `acquire` ~350 vs a real 513 forced a mid-apply
maintainer decision and a full reset — is exactly the failure mode a realistic
ceiling prevents. The 400-line *review* budget is tracked separately on the
hand-written portion and is NOT this number.

**Guard decision:** delivery strategy `ask-on-risk` + risk High → the orchestrator
presents the `size:exception` request to the maintainer at the Review Workload
Guard BEFORE `sdd-apply` launches. This artifact does NOT grant it.
